## 1. 기술 스택

| 구분 | 내용 |
|---|---|
| 언어 / 프레임워크 | Java 21, Spring Boot 3.4.5, Gradle |
| 데이터 | Spring Data JPA, 개발 H2(메모리) / 운영 MySQL(`prod` 프로필) |
| 인증 | JWT(HS384, 24시간), BCrypt 비밀번호 해시, 인터셉터 방식 |
| 테스트 | 53개: `PulseFlowTest` 33 · `PictureCatalogTest` 15 · `PictureServiceTest` 3 · `PictureControllerTest` 2 |

JWT 알고리즘은 jjwt가 시크릿 길이를 보고 골라요. 개발용 기본 시크릿(50바이트)에서는 HS384예요. 32~47바이트면 HS256, 64바이트 이상이면 HS512가 돼요.

### 구조

```
[iOS 앱 + 워치] ──HTTPS/JSON──▶ [Spring Boot API]
                                  ├ controller   요청 검증, 공통 응답
                                  ├ service      알림 판단, 인증, 기록, 마이페이지, 숨은그림 선택
                                  ├ repository   JPA, 그림 JSON 카탈로그(PictureCatalog)
                                  ├ entity       User · Alert · ActivityRecord · Mode · NextAction
                                  ├ dto          도메인별 요청·응답 record
                                  └ global/auth  JWT 인터셉터 (/auth 제외 전부 인증)
                                         │
                              [H2(개발) / MySQL(운영)]
테이블: users · alerts · activity_records
```

패키지(계층형): `controller` · `service` · `repository` · `entity` · `dto/{auth,alert,record,picture,user}` · `global/{auth,config,exception,response,util}`. Controller는 Entity와 Repository를 직접 다루지 않아요.

### 실행

- 개발: `./gradlew bootRun` (H2 메모리 DB, 별도 설정 없음). `ddl-auto: create-drop`이라 서버를 끄면 데이터가 지워져요.
- DB 확인: http://localhost:8080/h2-console (JDBC URL `jdbc:h2:mem:pulse;MODE=MySQL;DB_CLOSE_DELAY=-1`, 사용자 `sa`, 비밀번호 없음)
- 운영: `SPRING_PROFILES_ACTIVE=prod`, 환경변수 `DB_URL` `DB_USERNAME` `DB_PASSWORD` `JWT_SECRET` `PULSE_PUBLIC_BASE_URL`(그림 `imageUrl` 기준 주소, 없으면 기동 실패)
- 테스트: `./gradlew test` (53개)

## 3. 앞으로 개발할 것

### 3.1 OpenSpec 변경으로 진행

v0.2에서 모드(`COLOR` / `OBJECT`), 보호자 1명, 비밀번호 8자가 확정됐어요. API는 OpenSpec 변경 3개로 나눠 구현했어요. 구현이 끝난 `add-record-mode-next-action`과 `add-mypage-guardian`은 아카이브해 기준 스펙(`activity-record`, `user-profile`, `guardian-contact`)으로 합쳤고, 남은 변경은 `add-picture-next`뿐이에요. 진행률은 `openspec list`로 봐요.

| 순서 | 작업 | 명세 | OpenSpec | 상태 | 남은 확인 |
|---|---|---|---|---|---|
| 1 | 숨은그림 받기 `GET /pictures/next` | 5.1 | `add-picture-next` | 구현 완료, 작업 4개 남음 (팀 확정, 이미지 파일, 확정 좌표 반영) | 5장 3~6번 (고양이 수, 장면 수, 색 모드 대상, `emoji`) |
| 2 | 기록 `mode` 추가, 다음 행동 기록 `POST /records/{recordId}/next-action` | 6.1~6.3 | 기준 스펙 `activity-record` | 완료, 아카이브됨 | 기록 저장 시점 (`docs/화면흐름.md` 6장) |
| 3 | 마이페이지: 내 정보 조회·수정, 보호자 1명 등록·삭제 | 7.1~7.4 | 기준 스펙 `user-profile`, `guardian-contact` | 완료, 아카이브됨 | 5장 7~9번 (알림 기준값, 탈퇴, 통계), 11~12번 |

비밀번호는 팀 결정대로 8자 이상이라 서버에서 바꿀 것이 없어요. Figma의 "10자" 문구는 5장 2번에 적었어요.

### 3.2 데이터·운영 준비

- 숨은그림 데이터: 그림 이미지 저장 위치(CDN 또는 정적 파일)와 `targets`(x, y, radius) 확정 데이터 입력 (`add-picture-next`). 지금은 `catalog.json`에 명세 예시가 들어 있고 이미지 파일이 없어요.
- 운영 서버: 지금은 계획이 없어서 로컬 H2 + `create-drop`으로 개발해요. 서버가 생기면 `prod` 프로필(`ddl-auto: update`)로 DB를 연결하고 스키마 관리 방식을 정해요.
- 비밀값: `prod` 프로필은 `JWT_SECRET`과 `PULSE_PUBLIC_BASE_URL`을 필수로 받아요(2026-11-18 반영). 배포 환경은 서버 계획이 생기면 정해요.
- 로그인 실패 횟수 제한(무차별 대입 방지)

### 3.3 추후 논의

푸시 알림, 보호자 연락처, 토큰 갱신은 v0.2에서 정해져서 목록에서 뺐어요(명세 8.3).

| 항목 | 내용 |
|---|---|
| 사물 영역 형식 | 사물 모양이 다양하면 `x, y, radius` 대신 `x, y, width, height` 검토 |
| 알림 판단 고도화 | 서버 쪽 쿨다운(10분), 시간대별 기준, 최근 "괜찮아요" 이력 반영 |
| 통계 | 점수 변화(전→후) 추이 조회 API (5장 9번 마이페이지 통계와 함께) |
