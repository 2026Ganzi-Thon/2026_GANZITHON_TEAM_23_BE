|---|---|

## 1. 기술 스택

| 구분 | 내용 |
|---|---|
| 언어 / 프레임워크 | Java 21, Spring Boot 3.4.5, Gradle |
| 데이터 | Spring Data JPA, 개발 H2(메모리) / 운영 MySQL(`prod` 프로필) |
| 인증 | JWT(HS256, 24시간), BCrypt 비밀번호 해시, 인터셉터 방식 |
| 테스트 | `PulseFlowTest` (가입 → 로그인 → 심박 → 알림 거절 → 기록까지 한 번에 확인) |

### 구조

```
[iOS 앱 + 워치] ──HTTPS/JSON──▶ [Spring Boot API]
                                  ├ Controller   요청 검증, 공통 응답
                                  ├ Service      알림 판단, 인증, 기록
                                  ├ Repository   JPA
                                  └ JWT 인터셉터 (/auth 제외 전부 인증)
                                         │
                              [H2(개발) / MySQL(운영)]
테이블: users · alerts · activity_records
```

패키지: `auth` · `user` · `alert` · `record` · `global`(응답, 예외, 설정, 유틸)

### 실행

- 개발: `./gradlew bootRun` (H2 메모리 DB, 별도 설정 없음)
- 운영: `SPRING_PROFILES_active=prod`, 환경변수 `DB_URL` `DB_USERNAME` `DB_PASSWORD` `JWT_SECRET`
- 테스트: `./gradlew test`

### 개발 중 임의로 정한 값 (팀 확정 시 수정)

| 항목 | 현재 값 | 위치 |
|---|---|---|
| 알림 기준(평소 대비 상승폭) | 25bpm에서 시작 | `application.yml` `pulse.alert.base-threshold` |
| "괜찮아요" 시 기준 상승 | +5씩, 최대 45 | `pulse.alert.dismiss-step`, `max-threshold` |
| 알림 조건 | 걸음 없음(null 또는 0) + 상승폭 ≥ 기준 | `AlertService.report` |
| 이미 거절한 알림 재거절 | 기준값을 다시 올리지 않음 | `AlertService.dismiss` |
| JWT 만료 | 24시간 | `pulse.jwt.expiration-minutes` |
| 비밀번호 최소 길이 | 8자 | `AuthDtos.PASSWORD_MIN` |
| 활동 이름 | "숨은그림찾기" 고정 | `RecordService.DEFAULT_ACTIVITY` |

## 3. 앞으로 개발할 것

### 3.1 팀 확정 후 바로 진행 (우선순위 높음)

| 순서 | 작업 | 선행 확인 |
|---|---|---|
| 1 | 숨은그림 받기 `GET /pictures/next` | 아래 4번 "모드" 확정 |
| 2 | 기록 API에 모드(색 / 사물 / 현실 미션) 반영 | 모드 종류와 응답 필드 확정 |
| 3 | 마이페이지: 프로필 조회·수정, 보호자 연락처 저장 API | 프로필 항목, 보호자 1명 or 여러 명 |
| 4 | 비밀번호 규칙 반영 | 8자 / 10자 결정 |

### 3.2 데이터·운영 준비

- 숨은그림 데이터: 그림 이미지 저장 위치(CDN 또는 정적 파일)와 `targets`(x, y, radius) 초기 데이터 입력
- 운영 DB(MySQL) 연결, `ddl-auto: update` 대신 스키마 관리 방식 결정
- `JWT_SECRET` 등 비밀값 환경변수 분리, 배포 환경 결정
- 로그인 실패 횟수 제한(무차별 대입 방지)

### 3.3 추후 논의 (명세서 7장 기준)

| 항목 | 내용 |
|---|---|
| 푸시 알림 | 앱이 꺼져 있을 때 알림: 기기 푸시 토큰 등록 API + 서버 푸시 발송 |
| 사물 영역 형식 | 사물 모양이 다양하면 `x, y, radius` 대신 `x, y, width, height` 검토 |
| 보호자 연락처 | "보호자에게 문자"용 번호 저장 API (3.1의 3번과 함께) |
| 토큰 갱신 | accessToken 만료 시간, refresh 토큰 방식 |
| 알림 판단 고도화 | 서버 쪽 쿨다운(10분), 시간대별 기준, 최근 "괜찮아요" 이력 반영 |
| 통계 | 점수 변화(전→후) 추이 조회 API |

## 4. 팀에 확인해야 할 것

Figma와 명세서 v0.1 사이에서 어긋나는 부분이에요.

| 번호 | 항목 | Figma | 명세서 v0.1 | 영향 |
|---|---|---|---|---|
| 1 | 모드 | 색 / 사물 / 현실 미션 3가지 | 숨은그림찾기 1가지 | 그림 API, 기록 테이블 |
| 2 | 비밀번호 | 10자 이상 | 8자 이상 | 가입 검증 |
| 3 | 기록 목록 | 날짜 · 모드 · 시각 · 전→후 점수 | `activityName`만 있음 | 기록 응답에 `mode` 필요 |
| 4 | 다음 행동 분기 | 나아졌어요 / 한 번 더 / 다른 모드 / 도움 요청 | 해당 API 없음 | 서버 저장이 필요한지 확인 |
| 5 | 마이페이지·설정 | 프로필 등록, 보호자 이름 + 문자 연결 | 보호자는 "추후 논의"만 있음 | 새 API 필요 |
| 6 | 현실 미션 | 화면(08)이 있음 | 정의 없음 | 서버가 미션 문구를 내려줄지 |
| 7 | 알림 기준 | 정해진 값 없음 | "사용자별 기준값"만 있음 | 25bpm / +5 / 최대 45가 맞는지 |
| 8 | 도움 요청 | 109 · 1577-0199 · 119 전화 + 보호자 문자는 휴대폰 기본 앱으로 연결 | 서버 연동 없음 | 서버 작업 없음(앱 처리) |

> Figma 메타데이터가 커서 마이페이지(15), 설정(04), 현실 미션(08) 화면은 아직 자세히 읽지 못했어요. 이 화면들을 보고 3.1의 3번 설계를 확정해야 해요.
